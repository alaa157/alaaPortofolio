REST API Testing

Demo

Scope: Testing a sample REST API for a blog platform with CRUD endpoints, auth, and rate limiting.

Approach: Used Postman collections with environment variables. Verified status codes, response schemas, authentication tokens, error handling, and boundary inputs.

  • Confirmed 201/200/204/400/401/404/429 status code correctness
  • Found missing 400 response when empty body sent to POST /posts

Authentication & User Management QA

Demo

// QA Deliverable Sample

Sample bug report

A polished example of the defect documentation quality clients can expect. This is a demonstration report for a fictional issue on a demo application.

BUG-0041 High Severity Open
Title
Checkout fails with "Invalid shipping method" when selecting express delivery on mobile viewport
Environment
Chrome 120 / Safari 17 — Mobile (375px) — Staging build v2.4.1
Steps to Reproduce
1. Open demo-store.example on mobile viewport (375px width) 2. Add any product to cart 3. Proceed to checkout 4. Select "Express Delivery — 2-3 days" as shipping method 5. Tap "Continue to Payment" 6. Observe error banner: "Invalid shipping method selected" 7. Selecting "Standard Delivery" works normally
Expected Result
Express Delivery should be selectable and proceed to payment without error.
Actual Result
Error banner appears specifically for Express Delivery on mobile viewport. The same flow works on desktop (1440px).
Impact
Blocks mobile users from completing checkout with express shipping. Affects all products. Reproducible 100% of the time.
